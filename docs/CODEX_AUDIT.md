# ShelfScale independent audit

Auditor: Codex. Date: 2026-11-05 (America/New_York). Baseline: `16c3398c14dbe37870b061082b638ecdb6b3ecd3`; application code unchanged since `3077478`. Scope: scoring, import evidence, assessment/lookup/bulk paths, HTTP boundary, docs and queued work. This report is committed before implementation. Remediation status is appended in later commits.

## Findings, in severity order

1. **P1 — non-finite inputs can produce apparently valid scores.** `service._require_number`, `_positive`, `cofid_assess._number`, both scorers and traffic lights lack finite checks. Probe: energy `NaN` on otherwise zero nutrients yields score 0; lookup 14-834 with free sugars `NaN` yields a 2018 score of 1. Python JSON accepts NaN and Infinity by default. An integer `10**400` raises uncaught OverflowError; tiny positive gravity can overflow conversion. Negative optional `fat_g` is accepted and coloured green. Fix now: a shared finite-number validator, nonnegative nutrient validation, positive finite portions/gravity, finite derived amounts, strict JSON parsing/serialization, tests through supplied/lookup and bulk. Do not change band tables.
2. **P1 — public prototype has no access control or request rate limit.** `api.Handler.do_POST` directly dispatches all four routes. Large batches, repeated requests and stalled bodies can occupy threads. Fix in Phase 5: required key at startup, constant-time authentication for all assessment-producing POST routes (including lookup), bounded 60/minute limiter, timeouts, documented single-process scope. Hold its push for the Railway variable checkpoint. No live abuse/load test performed.
3. **P2 — malformed body framing can disconnect instead of returning JSON errors.** `api.py:61` casts Content-Length outside error handling; duplicate lengths/Transfer-Encoding are not rejected; reads lack a timeout. Fix now: reject ambiguous framing, invalid/missing/oversized lengths, invalid UTF-8/JSON, non-finite constants and excessive nesting with bounded error responses; timeout incomplete bodies. Add actual HTTP probes, preserving partial-success bulk semantics.
4. **P2 — 2018 inherits overly broad FVN groups and review is not machine-visible.** `cofid_assess.py` applies D/F/G after DA/DR exclusions to both models. SPEC §12 explicitly leaves DG tubers/seeds unresolved; GA/FA “flagged” currently means prose only. Phase 4: apply the owner's new tuber ruling to an explicit reviewed code list for 2018 only, add model-specific review flags and make caller FVN fallback labelling explicit. Preserve 2004/05 behavior and caller overrides; document a successor decision.
5. **P2 — assessment inputs cannot yet carry complete overlay provenance.** Lookup returns source/edition for observations, but assessment input labels hard-code CoFID and lack per-value release/period/supersession references. Phase 4 must preserve the original CoFID observations, attach exact match decisions, and replace only measured nutrients for established food matches. Milk measures only B2/B12/iodine; applying its label-derived macro data as laboratory data would be wrong. Beef has an official results ODS. Do not guess matches or replace whole food rows.
6. **P2 — reconciliation permits ambiguous/reused extraction rows.** `scripts/reconcile_fps.py` keys exact candidates by an unordered word set including brand and picks the first; exact candidates are not filtered by `used` (loose candidates are). This can conflate different portions or reuse a row. Phase 4: explicit food/portion key, unique matching, ambiguity report, deterministic rebuild and review of the six recorded disagreements. Retain transcription values; extraction agreement is not independent book verification.
7. **P2 — docs overstate current capabilities.** Bulk-limit error and API text direct callers to async jobs although no job route exists. `lookup.py` says lookup is not wired to HTTP; `api.py` says public hosting awaits authentication despite live Railway hosting. Update pipeline mentions open-data watching despite exclusion policy. Fix now: distinguish implemented and specified capabilities, advise splitting ranges, correct statements. Product surface, recipe calculator, reconstitution and jurisdiction-specific legal eligibility remain planned; a model score is not a compliance determination.
8. **P3 — test servers leak sockets.** Both HTTP test classes call shutdown but not server_close/thread join; baseline ends with two ResourceWarnings. Fix now in teardown; add boundary regressions where missing.

## Data and path verification

- `PYTHONPATH=src python3 -m unittest discover -s tests -v`: **103 pass in 6.156s**, two socket warnings. Full output in memory verification.
- Independent `zipfile`/ElementTree read of raw CoFID workbook: **2,887 nonempty food-code rows on each of 13 data sheets, 2,886 distinct codes, duplicate 13-669**. Initial audit regex excluded unusual code formats and counted 2,760; removed that erroneous format assumption and counted all source codes. Import yields **240,340 observations** with unique food IDs. Existing tests verify checksum refusal, bracketed values, methods and duplicate-code lookup. No manufactured uniqueness assumption.
- Direct CSV read: **2,652 FPS rows**; importer/tests reconcile **2,606 portions + 46 excluded**. 69 portion rows match 42 CoFID foods by unique exact name. Citation/rights guard passes; reviewed README, SPEC, register, source decision, report, importer and memory. FPS is NOT OGL and is never described as licensed; no contrary wording found. This is the owner's publication decision, not independent legal clearance; no physical book available to validate weights.
- Free sugars: `_npm2018_for_food` constructs a separate input map; no total-sugar substitution. `assess_product` → `assess_values`; `assess_bulk` → `run_bulk` → same single function; lookup bulk uses the same lookup function. Missing free sugars stays not scorable. Existing dual tests exercise both bulk paths. Non-finite bypass is finding 1.
- Rounding: scoring receives unrounded values; the only `round` calls in service are subsequent presentation. Density tests protect the milkshake boundary. Explicit per-volume density is required; CoFID Q uses its factor, other drink traffic lights report missing density. CoFID lookup 14-834 with free sugars 0 gives **5/true**, **1/false**.
- Boundaries/missing inputs: existing tests cover band edges, protein gates, missing fibre, boolean drink typing, duplicate codes, empty/no matches, partial success. New hostile-input/framing/1,001-item tests belong to remediation; baseline tests alone do not prove them.
